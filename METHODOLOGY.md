## 1. Цели тестирования

Перед любым реальным депозитом ответить на 4 вопроса:

1. **Есть ли edge?** — стратегия обыгрывает случайность?
2. **Сколько это стоит?** — после комиссий, спреда, slippage
3. **Насколько стабильно?** — на незнакомых данных, не только на истории
4. **Сколько денег приносит?** — в % годовых, с просадками

---

## 2. Этапы тестирования

### Этап 0. Базовая проверка стратегии

**Цель:** понять логику, найти баги в коде.

1. Прочитать код стратегии, понять каждый шаг
2. Прогнать на 1-2 тикерах, проверить что сигналы адекватны
3. **Искать lookahead bias** — использует ли стратегия будущие данные?
   - Сигнал в момент T не должен смотреть на свечу T+1
   - Проверить: `searchsorted(side="right")` для входа со следующей свечи
   - Same-candle TP+SL → LOSS (conservative)

### Этап 1. Скачивание данных

**Принцип:** чем больше данных и тикеров — тем лучше.

1. Определить вселенную тикеров (минимум top-50 по ликвидности)
2. Скачать минимум 2-3 года истории
3. Несколько таймфреймов: HTF (1D) + LTF (60M, 4H, 30M)
4. Источники:
   - MOEX ISS API (`iss.moex.com`) — акции, фьючерсы FORTS, индексы
   - Bybit V5 API (`api.bybit.com`) — крипта perp/spot
   - yfinance — золото, forex
5. **Проверить данные на аномалии**: нули, пропуски, split'ы без adjust

### Этап 2. Universe-бэктест (in-sample)

**Цель:** оценить есть ли вообще edge на полной вселенной.

1. Прогнать стратегию на каждом тикере отдельно
2. Параметры — авторские дефолты (не оптимизировать!)
3. Cost model — реалистичные комиссии (см. раздел 3)
4. min_rr фильтр — отбрасывать сигналы с R:R < порога

**Метрики:**
- Win rate (целевой > 60%)
- Total R (сумма R по всем трейдам)
- Expectancy = Total R / число сделок (целевой > +0.3R)
- Profit Factor = gross profit / gross loss (целевой > 1.5)
- Тикеров с edge vs без сигналов vs убыточных

**Фильтр аномалий:** отсечь тикеры с Total R > 500 (микро-неликвиды с нереалистичными R:R).

### Этап 3. Walk-Forward Optimization

**Цель:** проверить edge на незнакомых данных — это главный тест.

#### Метод: Anchored Expanding
```
Шаг 1: [IS: старт → мес.1] → [OOS: мес.2]
Шаг 2: [IS: старт → мес.2] → [OOS: мес.3]  ← IS растёт
...
Шаг N: [IS: старт → мес.N-1] → [OOS: мес.N]
```

#### Сетка параметров
Минимум 9 комбинаций:
```
sl_buffer: [3 значения] ×
min_rr:    [0.5, 1.0, 1.5]
swing:     зафиксировать на авторских (10/10)
```

#### Метрика оптимизации
**Expectancy** (средний R за трейд) на IS.
- Минимум 30 trades на IS для валидной оценки
- Если меньше — брать max-trades комбинацию

#### Два OOS-окна
- **1 месяц** — больше шагов, больше данных для анализа
- **3 месяца** — тише, надёжнее (каждый шаг на значимой выборке)

#### Ключевая метрика: OOS/IS ratio
```
OOS/IS = (avg expectancy на OOS) / (avg expectancy на IS) × 100%
```

| Значение | Интерпретация |
|---|---|
| **>70%** | ✅ Отлично — edge реальный |
| 50-70% | Приемлемо — edge слабее, но есть |
| 30-50% | Плохо — edge почти исчезает |
| <30% | ❌ Переобучение |

### Этап 4. Анализ доходности

#### 4.1. Risk model: 1% risk per trade
- Каждая сделка рискует 1% депозита
- До 5 одновременных позиций
- Сложный процент

#### 4.2. Risk model: Full Deposit
- LONG = 100% свободного депозита (без плеча)
- SHORT = 50% свободного депозита
- Пока позиция открыта — новые не открываются
- Реалистичнее для ручного трейдинга

#### 4.3. Помесячная разбивка
Для каждого прогона вывести по месяцам:
- Число сигналов
- Число взятых сделок (не пропущенных из-за нехватки депо)
- Win rate
- Доходность (%)
- Total R

**Целевые метрики:**
- Положительных месяцев: > 80%
- Худший месяц: > -10%
- Средний месяц: > +2%

#### 4.4. Годовая доходность
```
CAGR = (final_equity ^ (1/years) - 1) × 100%
```

### Этап 5. Сравнение с альтернативами

#### 5.1. Buy & Hold
Для каждого актива:
- Скачать цену на начало и конец периода
- Посчитать B&H return
- Сравнить с SMC return

**Стратегия имеет смысл только если обыгрывает B&H** хотя бы на части активов.

#### 5.2. Банковский вклад / облигации
Минимальная планка: стратегия должна обыгрывать безрисковую ставку (15-20% годовых для РФ).

### Этап 6. Breakdown анализ

#### Per-sector (для акций)
Разбить тикеры на сектора (нефтегаз, банки, металлурги, IT, утилиты).
Найти где edge сильнее/слабее.

#### Per-cap
Разбить на large / mid / small cap.
Проверить гипотезу «SMC работает только на ликвидных».

#### Per-year
Разбить по годам — падает ли edge со временем?
Нормально: WR снижается 85% → 75% за 3 года.

## 3. Cost Models (издержки)

### Принцип
Все прогоны — **после вычета комиссий**. Никогда не использовать zero-cost (кроме тестов ТФ).

### Формула
```
round-trip cost = 2 × (broker_rate + exchange_rate + spread + slippage) × position_value
```

### Площадки (верефицировано июль 2026)

| **Bybit spot API** | bybit-spot | **0.30%** | taker 0.1% × 0.70 + 10bps |

## 4. Баги и защита

### 4.1. R:R cap
Максимум 20:1. Всё выше — data noise (микро-OB зоны толщиной в копейки).
```python
if rr1 > 20:
    rr1 = 20.0
```

### 4.2. Relative min_risk
Если OB-зона почти нулевой толщины, SL ≈ entry → абсурдный R:R.
```python
min_risk = max(5 * pip, entry * 0.005)  # минимум 0.5% от цены
if risk < min_risk:
    sl = entry ± min_risk
```

### 4.3. Lookahead bias
- Вход строго со следующей свечи: `searchsorted(signal_time, side="right")`
- Same-candle TP+SL → LOSS (conservative)
- HTF swing_highs_lows: lookahead buffer на конце окна

### 4.4. Дублирование сигналов
Проверить что один OB не генерирует несколько сигналов.
Dedup по `(pair, ob_index, top, bottom)`.
